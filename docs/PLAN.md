# 四人連線開發計劃

## 目標與目前狀態

首版支援四位真人在同一房間完成基本版五輪遊戲，具備隱藏手牌、秘密影響力投票、正確結算、存檔及斷線重連。

目前已有規則整理、基礎數值 JSON、卡牌來源、SVG 原型與可執行的四人五輪試玩。

- `packages/engine` 處理五輪行動、企業與工人、發薪、食物需求、貸款、IMF、稅款、政策 1–7 的表決、輪末與終局計分。每輪補牌、更新人口並支付貸款利息。資本家與中產可出口庫存，並使用一次免費行動還貸或調薪。
- `apps/server` 提供四席房間、分席私人視圖、命令去重及房間快照。`apps/web` 以每 1.2 秒輪詢同步畫面，並使用專案 SVG 顯示手牌。
- 新房從目錄建立各角色 40 張行動牌。每個角色獨立洗牌抽七張，每輪保留未使用的兩張。企業、出口、綱領、事件、商業交易及移民牌庫獨立洗牌。資本家與中產可在準備階段選擇棄掉的市場牌，中產可選新增技術工技能。
- 財政政策或 IMF 變更公營企業時，由國家選擇開關企業與可用雇用配置。勞動市場與價格政策變更可觸發相關席位的即時調整。
- 全桌使用 10 張共用貸款卡。公司營收 0–4 暫按 0 稅額，終局最後一項平手比較暫以袋內各階級投票方塊數計算。
- 輪末計分支援勞工工會、中產繁榮、資本家財富與新高、國家事件懲罰、合法性及政治綱領。機械、自動化企業、罷工及示威已接上生產。
- 房長可從頁首的「調整」視窗即時修改四個階級的金錢、生活資源、商業倉庫庫存與容量，以及國家的公共庫存，方便現場校正實體桌狀態。商業倉庫容量以倉庫單位表示，公共庫存上限依已開放的公營企業容量。公共政策頁可調整七大政策、投票袋與國家事件，對外貿易頁可調整商務合約與出口牌，國家頁可調整各階級國家福利區的待領數字。

## 第一階段：補齊與驗證內容

基本版 325 張已建立目錄，234 個卡面 ID 與各組副本數均通過核對。數值資料與效果摘要放在 `data/hegemony-base-catalog.json`。107 個行動牌面及 25 個事件已映射到引擎。四席整合測試使用新版目錄跑完五輪，逐張裁決和跨卡互動仍待驗證。

- 建立牌組索引：160行動卡、59企業與合作農場、16出口、20交易、25移民、10綱領、25事件。
- 逐張核對原卡面，錄入前提、效果、合法性變動、副本數、選擇與限制。
- 補齊圖板人口表、兩套繁榮軌、合法性與影響力表、售價選項、倉儲及準備順序。
- 核對工人技能分布、投票方塊各色數及元件限制。
- 將FAQ例外轉成裁決記錄，區分已確認、待確認、開發假設。

完成條件：所有基本版內容有唯一ID、來源、校對狀態，副本總數吻合；阻擋欄位不再為null。資料未齊前只允許標示清楚的測試牌組。

## 第二階段：不依賴畫面的規則引擎

- 實作四角色狀態、工人與企業、庫存及有限供應區。
- 實作開局、準備、每人五回合、生產、選舉、計分與終局。
- 實作主要／免費行動限制、承諾工人、工會、罷工、示威、交易及繁榮。
- 實作稅表、雙帳資本、貸款、IMF與政策連鎖。
- 卡牌效果使用資料化操作及明確例外處理器。
- 建立可重播隨機、命令驗證、原子結算及事件日誌。

完成條件：以規格中的驗收案例驗證規則，能在無介面環境跑完五輪，重播得到一致終局狀態。

## 第三階段：四人連線與存檔

- 建立房間、四角色選位與席位身分恢復。
- 伺服器持有完整權威狀態，向每名玩家發送裁切視圖。
- 命令加入唯一ID與版本號，防止雙擊、重送及過期操作。
- 影響力秘密提交全部完成後同時揭露，不提前廣播數量或扣款。
- 存檔、快照、事件補傳與斷線重連；超時預設等待，不代替玩家做策略選擇。

完成條件：四個獨立客戶端同步；玩家無法取得他人手牌與牌庫順序；重連能回到未完成決策。

## 第四階段：遊戲介面

布局依[UI-LAYOUT.md](UI-LAYOUT.md)規劃，以使用者提供的BGA教學作分區與操作參考；四人新增區域另行設計，先驗證可點選原型再接完整引擎。

- 共用主板：政策、提案、企業、公營服務、供應區、出口、事件及輪次。
- 角色面板：資產、手牌、工人、繁榮／財富／合法性與可用行動。
- 引導式選擇：雇用、購買來源、事件、政策開關企業及投票。
- 顯示合法目標、成本、預期效果與拒絕原因。
- 日誌可追溯得分、資源流向及政策變動。

完成條件：四人可只依介面完成遊戲，重要選擇有明確提示；私人資訊不因UI同步而洩漏。

## 第五階段：完整對局驗收

- 四客戶端完成五輪與終局平手判定。
- 覆蓋罷工、示威、工人換位、供應不足、公營縮編、IMF、私有化等場景。
- 驗證秘密投票中重連、重複送命令、過期版本與保存恢復。
- 全部卡牌效果至少有對應案例；關鍵例外不得僅靠手動操作跳過。
- 確認部署及公開使用素材範圍，再準備發行。

## 建議架構（待實作時確定）

試玩採 Node.js 24、JavaScript 與瀏覽器原生介面。規則引擎與伺服器路由分開，每個命令在通過驗證後保存快照。完整版本再補決定性重播與事件傳輸，並按同步需求決定是否引入 WebSocket。

程式位於 `packages/engine`、`apps/server`、`apps/web` 與 `tests`。內容資料目前放在 `data`。
